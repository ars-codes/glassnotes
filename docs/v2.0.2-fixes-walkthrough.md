## 1. Summary of Changes & Fixes

### Fix 1: Deleting a Note Has No Effect
- **Files Modified**: [`ui/widget.py`](file:///d:/DEV/floatnote/ui/widget.py), [`ui/dialogs.py`](file:///d:/DEV/floatnote/ui/dialogs.py)
- **Root Cause**: `switch_to_note()` previously always called `flush_pending_save()`, which saved the editor's text to the active note. When `_delete_active_note()` called `storage.delete_note()` and then `switch_to_note()`, the flush recreated the deleted file immediately with the old text. Additionally, any unsaved debounce timer (`_save_timer`) could fire shortly after deletion and recreate it.
- **Key Changes**:
  - Added a `flush: bool = True` argument to `FloatNoteWidget.switch_to_note(category, filename, flush=True)`.
  - In `_delete_active_note()`, stopped `self._save_timer.stop()` before deleting.
  - Checked the return value of `storage.delete_note()`. If deletion fails, a modal [`AlertDialog`](file:///d:/DEV/floatnote/ui/dialogs.py#L349) is displayed instead of proceeding silently.
  - Switched to the resolved replacement note with `self.switch_to_note(next_cat, next_note, flush=False)`.
  - In `FloatNoteWidget.initialize()`, ensured `self._config["active_category"]` and `self._config["active_note"]` stay synchronized when specific category/filename arguments are passed.
  - Deleting the last remaining note cleanly triggers `storage.resolve_active_note()`, which safely recreates the default starter welcome note.

### Fix 2: Collapse/Expand Animation Content Reflow & Sliding on Right Screen Side
- **Files Modified**: [`ui/widget.py`](file:///d:/DEV/floatnote/ui/widget.py)
- **Root Cause**: The geometry animation interpolated both size and position, but window size limits (`setFixedWidth(FIXED_WIDTH)` and `setFixedSize(COLLAPSED_SIZE, COLLAPSED_SIZE)`) remained locked during animation. Qt clamped the intermediate sizes to the limits, animating only position. On the right side of the screen, the widget slid horizontally across ~230px before snapping size at the end. Additionally, note content reflowed and squished during the size transition.
- **Key Changes**:
  - At the start of `_run_collapse_animation()`, lifted size limits (`setMinimumSize(0, 0)` and `setMaximumSize(16777215, 16777215)`) so Qt freely interpolates size and position simultaneously.
  - Fixed the anchored corner across all frames: on the right side of the screen, `target_x = current_right - target_w` where `current_right = start.x() + start.width()`. Consequently, `x(t) + width(t) == current_right` remains constant for every frame.
  - Hid both `_expanded_container` and `_collapsed_btn` during the 150ms animation so note content never reflows, wraps, or slides sideways.
  - Consolidated constraint management into single-source helper methods: `_apply_expanded_constraints()` and `_apply_collapsed_constraints()`, used by `initialize()`, `_on_animation_finished()`, and invariant recovery checks.

### Fix 3: Size Invariant Enforcement & Interrupted Animation Recovery
- **Files Modified**: [`ui/widget.py`](file:///d:/DEV/floatnote/ui/widget.py), [`main.py`](file:///d:/DEV/floatnote/main.py)
- **Root Cause**: If an animation or hotkey toggle was interrupted mid-flight, or if display resolution/scaling changed, the widget could be left with incorrect or half-applied size constraints.
- **Key Changes**:
  - Added `_finish_animation_immediately()`: immediately stops any running QPropertyAnimation and jumps to the final state. Called before toggling, hiding, showing, or changing collapse state.
  - Implemented `_enforce_size_invariants()`: validates widget width and height against `COLLAPSED_SIZE` (when collapsed) or `FIXED_WIDTH` and `[MIN_HEIGHT, max_height]` (when expanded). Logs a warning if any mismatch occurs and restores the correct constraints and size.
  - Connected display configuration listeners (`screenAdded`, `screenRemoved`, `primaryScreenChanged`, `geometryChanged`, `availableGeometryChanged`) to re-enforce invariants and clamp to monitor boundaries.
  - Initialized `logging.basicConfig()` in `main.py` so diagnostic logs are captured.
  - Verified no hardcoded leftover sizes exist; all dimensions reference `FIXED_WIDTH = 288` and `COLLAPSED_SIZE = 58`.

### Fix 4: Stale Transparent Backdrop Layer Detection & Resync
- **Files Modified**: [`ui/widget.py`](file:///d:/DEV/floatnote/ui/widget.py)
- **Root Cause**: Native DWM / SetWindowCompositionAttribute acrylic backdrops can become desynchronized from Qt's logical geometry during complex resize or display transitions.
- **Key Changes**:
  - Implemented `_check_and_sync_native_geometry()`: queries the Win32 native window rectangle via `user32.GetWindowRect`, converts Qt logical geometry using `devicePixelRatio()` with 64-bit safe `argtypes` / `restype`, and checks for discrepancies.
  - If a mismatch exceeds high-DPI rounding tolerance, logs a warning and reapplies geometry; if still mismatched, forces `SetWindowPos` and reapplies the acrylic effect.
  - Hooked into `_on_animation_finished()`, `showEvent()`, `show_widget()`, and `ResizeHandle.mouseReleaseEvent()` (after drag-resize ends).
